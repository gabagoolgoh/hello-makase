Done when

You can tick the box before an open to-do to mark it done, and untick the box before a done one to reopen it, and the page no longer shows any Done or Undo buttons, only one box at the start of each row.

What

Each row of the list starts with a box: an empty ☐ for an open to-do and a ticked ☑ for a done one. Clicking it does what Done or Undo did. The row reads box, title, then the Delete button. Done to-dos stay struck through.

The box is not an <input type="checkbox">, because the page has no JavaScript and a real checkbox cannot submit anything by itself. It is the submit button of the row's existing form, drawn as a box. An open row's box sits in the method="post" form to /todos/{id}/done, and a done row's box in the form to /todos/{id}/undo. Each box therefore names the state it sets, never “toggle”, so a repeated click or a resubmitted form can never flip a to-do back (spec 003’s rule still holds).

For screen readers the button carries role="checkbox", aria-checked="true" or "false", and an aria-label holding the to-do’s title, escaped for an attribute. The box needs no visible word.

The routes do not change: /done, /undo and /delete keep their behaviour, redirects and errors. The remaining count, ids, order, Add and Delete all stay exactly as they are.

Touchpoints

  • app/main.py, item(todo): the Done/Undo form moves before the title, and its button shows ☐ or ☑ with role="checkbox", aria-checked and an escaped aria-label instead of the words Done or Undo. The Delete form is unchanged and stays after the title.
  • app/main.py, render(): the inline-form style rule is adjusted so the box sits before the title with space after it, and the box button looks like a box rather than a labelled button. Delete keeps its look.
  • tests/test_main.py: new tests for the cases below. The existing tests that look for <button type="submit">Done</button> or the word “Undo” in a row (among them test_undoing_a_done_todo_returns_it_to_open, test_unticking_a_title_keeps_it_escaped and test_a_done_todo_shows_undo_and_an_open_one_does_not) change to look for the box and its aria-checked, and still check the real method and action attributes.
  • Must not change: GET /, POST /todos, POST /todos/{id}/done, /undo and /delete and their status codes, add(), reset() and the id counter, the remaining-count wording, the strike-through of done titles, and title escaping.

Cases

  1. An open row starts with one form posting to /todos/{id}/done, whose only button shows ☐ with role="checkbox" and aria-checked="false".
  2. A done row starts with one form posting to /todos/{id}/undo, whose only button shows ☑ with role="checkbox" and aria-checked="true", and its title is struck through.
  3. Every row has exactly two real method="post" forms, in this order: the box, the title, then Delete.
  4. No row shows a button reading Done or Undo.
  5. Clicking an open row’s box (posting its form) answers 303 to /; that row then shows ☑, struck through, and the count drops by one.
  6. Clicking a done row’s box answers 303 to /; that row then shows ☐, not struck through, and the count rises by one.
  7. Posting the same box’s form twice leaves the to-do in the state the box named, not flipped back.
  8. Each box’s aria-label is its to-do’s title; a title holding <, & or " is escaped there and in the visible title, and does not break the attribute.
  9. An empty list renders no boxes and still offers the Add form.
  10. A newly added to-do shows an empty box.

Decisions

  1. A button drawn as a box, not a real checkbox: the operator chose it. It works with no JavaScript, keeps the explicit /done and /undo routes, and repeated clicks stay harmless. Rejected: a real <input type="checkbox"> with an inline onchange submit, which does nothing with JavaScript off and breaks the page’s plain-forms rule.
  2. No toggle route: the box posts to the state it sets, as spec 003 requires, so a double submit never re-ticks or unticks. Rejected: one /toggle route.
  3. The box before the title, Delete after: that is where people expect a checkbox. makase chose this.
  4. Done to-dos stay struck through: the tick and the strike say the same thing twice, which helps scanning, and keeping it limits the change. makase chose this.
  5. The boxes are the ☐ and ☑ characters: no images and no CSS drawing. The accepted cost is that their look varies slightly between fonts. makase chose this.
  6. Screen readers hear a checkbox: role="checkbox", aria-checked and the title as its label, so the change does not cost accessibility. makase chose this.
