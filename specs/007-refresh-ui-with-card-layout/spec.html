Done when

Each to-do row starts with one crisp checkbox button with no list bullet or double border, aligned cleanly with its title and quiet row actions. Ticking, unticking, editing, deleting, and adding all continue to work through plain HTML forms with screen-reader checkbox roles and labels preserved.

What

Today app/main.py renders the page on a plain white background with a bulleted <ul>, where each row’s checkbox puts a ☐ or ☑ character inside a second bordered <button>. This item refreshes the page to match The picked look (option c: “Give the whole page a soft card layout with row dividers and an accented Add button”): a soft card surface over a muted page background, a bullet-free list with horizontal dividers between rows, aligned row items, quiet row actions, and an accented Add button.

Every to-do row keeps its plain HTML form structure: the checkbox remains an enabled <button type="submit"> inside form.done (posting to /todos/{id}/done) for open items and form.undo (posting to /todos/{id}/undo) for done items, carrying role="checkbox", aria-checked="false" or "true", and aria-label set to the HTML-escaped title. Instead of placing ☐ or ☑ inside a bordered button, the button has no box-glyph text and is drawn directly in CSS as one crisp square box with a CSS-drawn checked state when done.

Rows lay out horizontally with flex alignment so the checkbox, title, and trailing row actions align cleanly even when titles wrap. Because this item rests on 006 — Edit a to-do’s title, each normal row carries the checkbox form, its title (wrapped in <s>...</s> when done, with no page style cancelling line-through), the quiet Edit link (<a href="/?edit={id}">), and the quiet Delete form (form.delete posting to /todos/{id}/delete). When a row is open in edit mode via GET /?edit={id}, its inline edit form (text input, Save button, and Cancel link to /) fits cleanly inside the card row without overflowing or breaking row dividers. When the list is empty, the card renders no list rows and still displays Nothing left and the accented Add form.

This item does not add JavaScript, native <input type="checkbox"> controls, toggle routes, static CSS asset files, persistence, or any change to routes, status codes, ids, or remaining-count text.

Merge gate check (by hand): open the to-do page in Test and compare it with The picked look: confirm the soft card layout, absence of list bullets, clean row dividers, crisp single-border CSS checkboxes in open and done states, aligned titles with quiet Edit and Delete controls, an inline edit row when clicking Edit, and the accented Add button.

Cases

  1. On GET /, every open row renders <li class="todo"> starting with a method="post" form to /todos/{id}/done containing one enabled <button type="submit" role="checkbox" aria-checked="false"> labelled with the title and containing neither ☐ nor ☑.
  2. On GET /, every done row renders <li class="todo done"> starting with a method="post" form to /todos/{id}/undo containing one enabled <button type="submit" role="checkbox" aria-checked="true"> labelled with the title, containing neither ☐ nor ☑, and displaying its title inside <s>...</s> with no page CSS cancelling line-through.
  3. The page’s <style> block suppresses list bullets (list-style: none), lays out rows as aligned flex items with dividers, styles the card container, CSS checkbox states, quiet row controls, and accented Add button, and adds no native <input type="checkbox">.
  4. Every non-editing row keeps the DOM order checkbox form, visible title, Edit link (href="/?edit={id}"), and Delete form (method="post" action="/todos/{id}/delete"), with no visible Done or Undo button text.
  5. Submitting an open row’s rendered checkbox form (POST /todos/{id}/done) returns 303 to / and reloads with aria-checked="true", <s> strike-through, and remaining count down by one; submitting a done row’s checkbox form (POST /todos/{id}/undo) returns 303 to / and reloads with aria-checked="false", no <s>, and remaining count up by one.
  6. Submitting the same rendered open or done checkbox form twice leaves the to-do in the state that form named, never toggling it back.
  7. Submitting a non-blank title through the Add form (POST /todos) returns 303 to / and renders a new unchecked CSS checkbox row with Edit and Delete while raising the remaining count by one; submitting a blank or whitespace-only title redirects 303 to / with the list and count unchanged.
  8. Requesting GET /?edit={id} renders only that row as a method="post" form to /todos/{id}/edit with the title input, Save, and Cancel (and no checkbox or Delete) while every other row keeps its refreshed markup; saving a new title answers 303 to / and updates both the visible title and the checkbox aria-label, while saving a blank title or clicking Cancel leaves title and tick unchanged.
  9. Submitting a row’s Delete form (POST /todos/{id}/delete) returns 303 to / and removes the row; deleting every to-do leaves an empty <ul> with no <li> rows, no checkbox buttons, Nothing left, and a working Add form.
  10. Posting to /todos/{id}/done, /undo, or /edit for an unknown or deleted id returns 404 (while /delete redirects 303), posting a non-integer id returns 422, and requesting GET /?edit= with an unknown, deleted, or non-integer id returns 200 with the normal card list and no row in edit mode.
  11. A title containing <, &, and " stays HTML-escaped in the visible title (open and done), the edit input value, and the checkbox’s aria-label attribute without breaking markup.

The picked look: Give the whole page a soft card layout with row dividers and an accented Add button

Decisions

  1. Soft card layout with row dividers and accented Add button (1/1/c): the operator picked option c from the three previewed levels of polish (The picked look); rejected option a (checkbox and bullets only on a plain page) and option b (row alignment and controls on a plain white page, recommended by makase) because the operator wanted the full card framing and accented Add button.
  2. CSS-styled checkbox button instead of ☐/☑ glyphs or native inputs: keeps the button as a plain HTML <button type="submit"> inside form.done/form.undo with role="checkbox", aria-checked, and aria-label while eliminating the double border and cross-font glyph mismatch; rejected keeping Unicode glyphs inside a bordered button (clunky double border) and rejected <input type="checkbox"> with JavaScript submit (violates the no-JS plain-form rule).
  3. Rest on 006 — Edit a to-do’s title: landing item 006 first ensures the new Edit link and inline edit row share the quiet row styling and card alignment in one pass rather than styling rows before Edit exists.
  4. Update item 005’s glyph assertions in tests/test_main.py (chosen by makase): removing the double-boxed ☐/☑ characters intentionally breaks old literal-glyph checks, so those tests switch to checking CSS-checkbox semantics and absence of the glyphs while preserving every form-submission, ordering, and escaping check.
  5. Keep all CSS inline in render()’s <style> block (chosen by makase): avoids adding static-file mounts or asset pipelines so app/main.py stays one self-contained module, consistent with the vision and trivial to split out later if needed.
  6. Preserve <s> strike-through and quiet secondary row actions (chosen by makase): done rows keep <s> with line-through intact alongside the checked CSS box, and Edit and Delete use a quiet secondary style so Add remains the page’s single primary accent control.
  7. Keep one HTML source line per <li> and preserve class="todo" / class="todo done" (chosen by makase): preserves existing test helpers (rendered_item, rendered_list_items) and DOM structure while letting CSS handle all visual layout.
