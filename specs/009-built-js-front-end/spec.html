Done when

Building the front end produces a working to-do page that loads, adds, completes, undoes, edits, and deletes items via the JSON API without full-page reloads. Opening the app in Test serves the built UI, and the old server-rendered routes are removed.

What

Add a separate Vite-based JavaScript front end in frontend/ that builds to frontend/dist/ and consumes the /api/todos JSON API via fetch with no full-page reloads. Wire FastAPI in app/main.py to serve the built front end at /, remove the old server-rendered HTML helpers and form-post routes, and update makase-runbook.toml so Test builds and serves the built UI.

The built page reproduces the single-card to-do interface and handles all interactions in place:

  • Load — fetches GET /api/todos on startup, renders the heading, remaining counter ("Nothing left" when 0, otherwise "{remaining} left"), and each to-do row with titles rendered as plain text (never parsed as HTML).
  • Add — submitting a non-blank title sends POST /api/todos, appends the returned item, clears the input, and updates the remaining counter; blank submissions are ignored or show an inline error without mutating the list.
  • Complete and undo — clicking a row's checkbox sends PATCH /api/todos/{id} with {"done": !todo.done} and updates the row's done styling and remaining counter.
  • Edit — clicking Edit switches the row to an inline input pre-filled with the title plus Save and Cancel; Cancel exits edit mode without an API call, and Save sends PATCH /api/todos/{id} with the trimmed title (rejecting blank titles).
  • Delete — clicking Delete sends DELETE /api/todos/{id}, removes the row, and updates the remaining counter.
  • Errors — if any API request fails (e.g., 404, 422, or network failure), displays a visible error message without crashing or losing the rest of the list.

This item does not add persistence, user accounts, or multiple lists.

By-hand check for the merge gate: open the app in Test at /, confirm the starter to-dos appear, and add, complete, undo, edit, and delete an item while verifying no full-page reload occurs.

Touchpoints

  • frontend/package.json (new file) — Vite dependencies and build / dev scripts.
  • frontend/vite.config.js (new file) — Vite configuration with /api proxy to http://127.0.0.1:8000 for local dev.
  • frontend/index.html (new file) — HTML entry point for the Vite build.
  • frontend/src/main.js and frontend/src/style.css (new files) — client application consuming /api/todos and card styles.
  • app/main.py — remove item(), edit_item(), render(), and the old form-post routes (POST /todos and POST /todos/{todo_id}/*); serve frontend/dist at / (and built assets) mounted after /api routes.
  • makase-runbook.toml — update start so Test installs/builds frontend/ and starts uvicorn app.main:app serving the built UI at opens = "/".
  • tests/test_main.py — replace tests targeting the removed server-rendered HTML/form routes with tests verifying GET / serves the built UI and the old form-post routes are removed.
  • tests/test_api.py — must continue passing unchanged.
  • .gitignore — ignore frontend/node_modules/ and frontend/dist/.

Cases

  1. Running the front-end build (npm run build in frontend/) exits 0 and outputs frontend/dist/index.html and bundled assets.
  2. GET / on FastAPI returns 200 text/html serving frontend/dist/index.html, and built asset URLs under /assets/ return 200.
  3. Old server-rendered form routes (POST /todos, POST /todos/1/done, POST /todos/1/undo, POST /todos/1/edit, POST /todos/1/delete) are removed and return 404 or 405.
  4. Initial load fetches GET /api/todos and renders all returned items plus "N left" (or "Nothing left" when 0).
  5. Submitting a non-blank title sends POST /api/todos, appends the created item, clears the input, and updates the remaining count without a page reload.
  6. Submitting a blank or whitespace-only title does not send a create mutation or add a blank item.
  7. Toggling a checkbox sends PATCH /api/todos/{id} with {"done": true} for open items and {"done": false} for done items, updating the row and remaining count.
  8. Clicking Edit opens an inline input with the item's title; clicking Cancel closes it without calling PATCH; saving a non-blank title calls PATCH /api/todos/{id} and updates the row; saving a blank title does not overwrite the item.
  9. Clicking Delete sends DELETE /api/todos/{id}, removes the row, and updates the remaining count.
  10. A title containing HTML markup (such as <b>bold</b>) renders as literal text rather than parsed HTML.
  11. An API error response (404 or 422) renders a visible error message without crashing or clearing the list.

Decisions

  1. Separate built JS front end with Vite (operator choice): add a Vite build in frontend/ as the API's first consumer; rejected plain static JS with no build step (makase's recommendation) because the operator chose a separate built front end.
  2. Vanilla JS inside Vite (makase chose this): keeps the client small, dependency-light, and easy to read for a single-page to-do list; rejected adding a larger UI framework like React or Vue.
  3. Serve frontend/dist from FastAPI in Test (makase chose this): mounting the built static files in FastAPI after /api routes lets one start command in makase-runbook.toml serve both the UI and API on port 8000 with no CORS setup; rejected running two separate servers in the runbook.
  4. Remove old server-rendered HTML and form routes: delete render(), item(), edit_item(), and POST /todos* now that the built UI replaces them, leaving a single UI path.
  5. Gitignore frontend/node_modules/ and frontend/dist/ (makase chose this): keep generated dependencies and build outputs out of git and build them during setup/start in makase-runbook.toml.
