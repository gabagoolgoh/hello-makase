Expose JSON endpoints in FastAPI for listing, creating, updating, and deleting to-dos.

Done when

Calling the JSON endpoints with TestClient lists, adds, completes, undoes, edits, and deletes to-dos in memory and returns JSON errors for missing items or blank titles. The existing server-rendered routes keep working until the new front end replaces them.

What

Add a JSON API under /api/todos in app/main.py backed by the existing in-memory todos list, Todo dataclass, next_id counter, add(), and reset(). All existing server-rendered HTML and form-post routes (GET /, POST /todos, and POST /todos/{todo_id}/*) remain intact and continue sharing the same in-memory state until the built front end replaces them.

Each to-do serializes as {"id": int, "title": str, "done": bool} with the raw, unescaped title string. The endpoints are:

  • GET /api/todos — returns 200 with {"todos": [...], "remaining": int}, where todos preserves insertion order and remaining is the count of items with done == false.
  • POST /api/todos — accepts JSON {"title": str}, trims surrounding whitespace, and rejects missing or blank titles with 422 JSON {"detail": ...}. On success, appends via add() and returns 201 with the created item.
  • PATCH /api/todos/{todo_id} — accepts JSON with optional title and/or done fields. Returns 404 JSON {"detail": ...} if todo_id is not in todos. If title is provided, trims it and returns 422 JSON {"detail": ...} without modifying the item when blank. If done is provided, sets todo.done (supporting both completing and undoing, idempotently). Returns 200 with the updated item.
  • DELETE /api/todos/{todo_id} — removes the item from todos in place and returns 204. Returns 404 JSON {"detail": ...} if todo_id is not in todos.

This item does not add a JavaScript front end, static file serving, persistence across restarts, authentication, or multiple lists, and does not modify or remove any existing server-rendered route or test in tests/test_main.py.

Touchpoints

  • app/main.py — keep app, Todo, STARTERS, todos, next_id, reset(), add(), and all existing HTML/form routes unchanged; add Pydantic request/response models and the GET /api/todos, POST /api/todos, PATCH /api/todos/{todo_id}, and DELETE /api/todos/{todo_id} route handlers.
  • tests/test_api.py (new file) — TestClient(main.app) test suite for the JSON endpoints, using an autouse fixture calling main.reset().
  • tests/test_main.py — must not change; all existing server-rendered tests must remain green.

Cases

  1. GET /api/todos on a fresh app returns 200 with the 5 starter to-dos in order and remaining: 4.
  2. GET /api/todos when todos is empty returns 200 with {"todos": [], "remaining": 0}.
  3. POST /api/todos with {"title": " Fix the bike "} trims the title, appends a new item with done: false and a fresh id, and returns 201 with that item; a subsequent GET /api/todos includes it and increments remaining.
  4. POST /api/todos with an empty or whitespace-only title returns 422 JSON error and leaves todos unchanged.
  5. POST /api/todos with a missing title field or invalid JSON body returns 422 JSON error and leaves todos unchanged.
  6. PATCH /api/todos/{id} with {"done": true} marks an open item done, returns 200 with done: true, and decrements remaining in GET /api/todos.
  7. PATCH /api/todos/{id} with {"done": false} undoes a done item, returns 200 with done: false, and increments remaining in GET /api/todos.
  8. PATCH /api/todos/{id} repeating {"done": true} on an already-done item (or {"done": false} on an open item) is idempotent and returns 200.
  9. PATCH /api/todos/{id} with {"title": " New title "} updates the title to "New title" (preserving raw characters such as <b> without HTML-escaping) and returns 200.
  10. PATCH /api/todos/{id} with an empty or whitespace-only title returns 422 JSON error and leaves the item's title unchanged.
  11. PATCH /api/todos/{id} for a non-existent id returns 404 JSON error.
  12. DELETE /api/todos/{id} removes the item, returns 204, and a subsequent GET /api/todos omits it without reusing its id on later adds.
  13. DELETE /api/todos/{id} for a non-existent id or a repeated delete of the same id returns 404 JSON error.
  14. Existing server-rendered routes (GET / and POST /todos*) continue to return HTML/redirect responses and share the same in-memory todos list.

Decisions

  1. API-first JSON backend alongside existing routes: add JSON endpoints now while keeping the server-rendered routes working until the JS front end replaces them — avoids breaking the app between cards; rejected replacing HTML routes in-place before a client exists.
  2. Namespace JSON endpoints under /api/todos (makase chose this): avoids colliding with the existing form-post /todos routes during the transition; rejected content-negotiation on /todos because form posts and JSON clients expect different status codes and bodies.
  3. Single PATCH /api/todos/{todo_id} endpoint for done, undo, and title edits (makase chose this): one partial-update endpoint handles both done and title cleanly; rejected separate /done, /undo, and /edit JSON action routes as unnecessary duplication.
  4. Return 422 for blank titles and 404 for missing items on PATCH and DELETE (makase chose this): explicit JSON errors let the JS client detect and report invalid input or missing items instead of silently ignoring them like the form-post routes did.
  5. Keep in-memory storage: preserve todos, STARTERS, and reset() with no database — keeps scope focused on the API/client split and keeps TestClient tests fast.
