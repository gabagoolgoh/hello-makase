Done when

You can press Edit beside any to-do, change its title in the field that opens, press Save, and see the new title in the same place on the page, with its tick, its position and every other to-do unchanged; and you can press Cancel instead to leave it as it was.

What

Every row gets an Edit link after its title, before Delete. The link is a plain <a href="/?edit={id}">, not a form, because opening the editor changes nothing. GET / with edit naming a to-do on the list draws that one row as an edit form instead of its usual contents: a method="post" form to /todos/{id}/edit holding a text input named title, filled with the current title (escaped for an attribute) and labelled for screen readers, a Save submit button, and a Cancel link to /. While a row is being edited it shows no checkbox and no Delete. Every other row is drawn exactly as without edit. Only one row is edited at a time.

POST /todos/{todo_id}/edit trims the submitted title. If something is left, it replaces the to-do’s title. If nothing is left, the title stays as it was, as Add ignores a blank title. Either way it answers 303 to /. The to-do keeps its id, its done flag and its place in the list, and done to-dos can be edited like open ones. An id that is not on the list answers 404 and changes nothing, like Done and Undo.

A GET /?edit= value that names no to-do on the list (unknown, deleted, or not an integer) draws the normal page, with no row in edit mode and no error.

The remaining count, Add, the checkbox and Delete keep their behaviour and look. Titles stay escaped everywhere.

Touchpoints

  • app/main.py, page() (GET /): accepts an optional edit query value and passes it to render(). An invalid value must not produce a 422.
  • app/main.py, render(): takes an optional id of the row to edit, defaulting to none, so existing callers draw the page as today; it draws that row as the edit form.
  • app/main.py, item(todo): adds the Edit link after the title and before the Delete form, in both the open and done rows. A row still holds exactly two forms (box and Delete).
  • app/main.py, the page’s inline style: the Edit link and the edit form sit inline in the row, in the same quiet style as Delete.
  • app/main.py, new route POST /todos/{todo_id}/edit taking form field title.
  • tests/test_main.py: new tests for the cases below. Existing row tests keep passing; where one asserts a row’s exact contents, it is updated to allow the Edit link and nothing else.
  • Must not change: POST /todos, /done, /undo, /delete and their status codes, add(), reset() and the id counter, the remaining-count wording, the checkbox markup and its aria-* attributes, and the order of the list.

Cases

  1. Every open row and every done row has an Edit link to /?edit={id}, after the title and before Delete, and still exactly two forms.
  2. GET /?edit={id} for a to-do on the list draws that row as one method="post" form to /todos/{id}/edit with a title input holding the current title, a Save submit button, and a Cancel link to /; that row has no checkbox and no Delete.
  3. In that page every other row is identical to its row on plain GET /.
  4. Saving a new title answers 303 to /; the page shows the new title in the same position, with the same id, and the old title is gone.
  5. Saving a done to-do’s title keeps it done and struck through; saving an open one keeps it open; the remaining count does not change.
  6. Saving a title with spaces around it stores it trimmed.
  7. Saving a blank or all-spaces title answers 303 to / and leaves the title unchanged.
  8. Saving the same title it already has answers 303 to / and changes nothing.
  9. Saving an id not on the list (never existed, or deleted) answers 404 and changes no to-do.
  10. POST /todos/not-an-int/edit is refused with 422 and changes nothing.
  11. GET /?edit= with an unknown id, a deleted id, or a non-integer draws the normal page with 200 and no row in edit mode.
  12. A title holding <, & or " is escaped in the input’s value without breaking the attribute; saving such a title shows it escaped in the row and in the checkbox’s aria-label.
  13. Saving a new title for one to-do leaves every other to-do’s id, title, done flag and order unchanged.

Decisions

  1. Edit opens with a link, /?edit={id}: opening the editor changes nothing, so it is a GET link, not a form. Every row therefore keeps exactly two forms, as items 004 and 005 require. Rejected: an always-visible text field on every row, which clutters the list; and JavaScript in-place editing, which the page has none of. makase chose this.
  2. The row being edited hides its checkbox and Delete: no ticking or deleting a to-do halfway through renaming it, and the row holds one clear form. makase chose this.
  3. One row at a time: edit takes one id. makase chose this; editing several at once was not asked for.
  4. A blank save keeps the old title: it mirrors Add ignoring a blank title. Rejected: treating a blank save as delete, which would make a slip of the backspace key destroy a to-do. makase chose this.
  5. Saving an unknown id is 404: like Done and Undo, an edit needs a to-do to act on. Delete redirects instead only because a gone to-do is what Delete wanted. makase chose this.
  6. A bad ?edit= shows the normal page: a stale or mistyped link should not land on an error page for a view that changes nothing. makase chose this.
  7. Editing keeps the tick, the id and the position: a rename is only a rename. makase chose this.
